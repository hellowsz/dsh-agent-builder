# builder —— 对话式搭建助手

和用户聊清需求,选并组合插件,跑样例验证,最后固定成一份 DSH 配置文件。

## 一次搭建的步骤(草案)

1. **收敛需求**:通过对话问清——干什么任务、输入是什么、交付物长什么样、什么算合格。
2. **选插件**:从 `plugin-registry` 的清单里挑能覆盖需求的插件;缺的记下来(可能要自建)。
3. **组合**:把选中的插件拼成一份候选配置(声明加载哪些、怎么接线)。
4. **测试**:跑一批多样化样例,产出交付物给用户看。
5. **报告**:给出稳定性报告(通过率、会翻车的情况)。
6. **固定**:用户确认后,输出最终 yml,可直接在 DSH 加载。

## 现状

草案。先随 MVP 的窄场景把这条链跑通,再抽象成通用流程。
