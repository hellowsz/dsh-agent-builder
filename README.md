# dsh-agent-builder

用对话搭一个能**稳定交付结果**的 agent,产物是一份可组合的 DeepSeek Harness 配置文件(yml),固定后直接在 DeepSeek Harness 里运行。

## 它是什么

- 你和一个"搭建助手"聊:要干什么、给它什么输入、想要什么样的交付物。
- 搭建助手挑选并组合需要的插件,跑一批真实样例做测试,给你一份**稳定性报告**(跑了多少个样例、通过多少、哪些情况会翻车)。
- 你确认后,它把这套配置**固定成一份 yml**。以后加载这份 yml,就得到一个装配确定、行为一致的 agent。

## 和可视化编排工具的区别

那类工具的编排层本身带模型的不确定性;这里的产物是**声明式装配**——加载哪些插件、怎么接线,是确定的代码路径,不靠模型临场猜。同一份 yml,装出来的能力骨架每次一样。

需要说清的一点:yml 固定的是**能力骨架**,不是模型每次吐出的**内容**。内容的稳定靠"固化前多样例测试 + 可检验的验收标准 + 稳定性报告"来压,这是本项目的核心工作,不是底座自动送的。

## 目录

- `builder/` —— 对话式搭建助手:收敛需求 → 选插件 → 跑样例 → 生成 yml。
- `plugin-registry/` —— 开源插件收集器:定时抓取好用、高 star 的插件,整理成可被搭建助手检索的清单。
- `docs/` —— 定位取舍、MVP 边界、稳定性验证机制等设计说明。

## 现状

规划阶段。先打通一个窄场景的完整链路(对话配置 → 生成 yml → DSH 里跑 → 多样例稳定性报告),验证"产出能不能被信任",再谈通用组合。见 `docs/vision.md`。
