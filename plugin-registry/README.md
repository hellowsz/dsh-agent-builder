# plugin-registry —— 开源插件生态仓库（规划）

> 定稿方向(2026-08-18):这部分会**独立成一个仓库**,作为依赖 DeepSeek Harness 的生态仓库,由定时 agent 自动全网收集插件,**面向 AI 接入,不是给人翻阅**。当前目录只是占位与规划,后续拆出去独立维护。

## 定位

- **独立仓库**:和 dsh-agent-builder 主仓分开,单独一个依赖 DSH 的生态仓库。
- **定时 agent 自动收集**:一个独立的定时任务 agent,全网自动筛选好用、高 star 的开源 DSH 相关插件并入库,不靠人工维护。
- **面向 AI 接入**:产出的清单是给搭建助手(AI)检索、挑选、接入用的,不是给人看的目录。

## 收集流程（草案）

1. **发现**:定时 agent 在公开代码仓库按关键词/主题检索候选插件,记录来源地址。
2. **筛选**:按 star 数、最近更新时间、是否符合 DSH 插件形态(导出 `apply` 等)过滤。
3. **核验**:确认插件声明的能力、依赖、注入项;标注是否需要密钥、是否有网络副作用。
4. **入库**:写入清单,每条含名称、来源、能力摘要、star、最近更新、可信度标注。
5. **定时更新**:周期性重跑,刷新 star 与更新时间,淘汰失活项。

## 清单条目字段（草案，面向 AI 检索）

- 名称 / 来源地址
- 能力摘要(一句话说清它能干什么)
- star 数 / 最近更新时间
- 依赖与注入项
- 是否需要密钥、是否有外部副作用
- 可信度标注(已核验 / 待核实)

## 注意

- 收集回来的是**第三方代码**,入库不等于可信。默认按"待核实"标注,给搭建助手看清来源,由它在接入时判断。
- 未经核验的能力名、API 名不编造,查不到就标"待核实"。
