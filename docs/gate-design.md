# 验证门禁设计

> 承接 `vision.md` 里定的"每个 agent 一套专属验证门禁"。飞书对齐稿:https://www.feishu.cn/docx/WFxrdIx35o5m4vxnc6hcPDpLn6b

门禁 = 给每个 agent 配的一叠"验收检查",在它交付结果前拦一道:能用确定性规则判的绝不靠 AI,拦下不合格产出,重试或让用户挑降级方案。

## 一、形态:分层检查

四层,从便宜可靠到昂贵模糊,按顺序跑,任一不过即拦下:

| 层 | 检查 | 可靠性 |
|---|---|---|
| ① 结构检查 | 格式、字段、类型、范围 | 确定性 |
| ② 规则检查 | 业务硬约束(金额=明细之和、日期不晚于今天) | 确定性 |
| ③ 对照检查 | 产出对得上输入、引用必须在原始资料出现过(防编造) | 大多确定性 |
| ④ AI 评审 | 结构管不到的(完整性、切题),交给**独立评审 agent** 打分 | 模糊,兜底 |

原则:把用户说的"什么算合格"尽量翻译成 ①②③,④ 只补前三层补不到的。确定性检查占比越高越稳。

## 二、生成:固化时造,门禁本身也要被验

搭建助手固化 agent 时:

1. **问清合格标准**:据情况主动追问或用样例反推,交互统一走**清单勾选**(不让新手写规则,只让他勾)。
2. **造门禁**:把勾选项翻译成 ①②③ 检查,④ 配评审 agent 的打分要求。
3. **验门禁**:拿好样例 + 故意弄坏的样例各跑一遍——好的必须过、坏的必须拦。放行一切的门禁等于没有。

## 三、运行时:挂 DeepSeek Harness 原生扩展点

调研 `~/self/deepseek-harness` 后确认,无需外层包壳:

| 要做的事 | DSH 扩展点 | 出处 |
|---|---|---|
| 交付前拦一道 | `agent/turn-stopping` 事件 | `packages/core/agent/src/runtime-types.ts` |
| 不合格→带原因重试 | `agent.steer(...)` 重开回合再跑 | 同上 |
| 每 agent 专属门禁 | 门禁插件挂进该 agent 的 preset,作用域隔离 | `ctx.agentPresets` |
| 防死循环 | 自设重试上限(参考 `goal-round-driver` 的 round-limit) | `packages/goal/goal-round-driver` |
| 把合格标准喂给 agent | `ctx.systemPrompt.section` 注入(模板 `agent-instructions`) | `packages/core/system-prompt` |
| 拦工具产出(可选) | `tools/post-execute` 的 `block` | `packages/core/tools` |

流程:产出候选 → 门禁检查(①②③ + ④独立评审)→ 过则交付;不过且还能重试 → 喂回原因重跑;重试用尽 → 生成降级方案清单,用户勾选(带标注交付 / 换输入 / 转人工 / 放弃)。

注:DSH 只给"拦截机制"不给"判据",①②③④ 的检查逻辑要自己实现——这是本项目核心工作量,判据质量 = 稳定性。

## 四、门禁定义放哪(已决策)

**独立的声明式门禁文件,一个 agent 一份;由一个通用门禁插件加载执行,通过 preset 挂到对应 agent。**

- **解耦**:判据和 agent 配置分开,可单独版本化、diff、复用。
- **可沉淀模板**:好门禁能进生态仓库,给同类 agent 直接套。
- **加检查不动存量**:新增检查类型只改门禁插件,不动每个 agent。
- 不选嵌进 agent 主 yml——会耦合、膨胀、没法复用。

## 五、已定决策(存档)

1. 失败兜底:可降级交付,但**生成降级方案清单让用户勾选**,不静默。
2. AI 评审:要,且是**独立评审 agent**。
3. 门禁定义:独立声明式文件 + 通用插件 + preset 挂载(见第四节)。
4. 新手定标准:追问或样例反推据情况来,交互统一**清单勾选**。
