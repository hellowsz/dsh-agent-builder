# MVP:报销单据整理助手

> 首发场景。飞书对齐稿:https://www.feishu.cn/docx/PB9XdFzomoHQyMx9G50c8irHnDm

把一段原始费用信息(文字)整理成一张结构化报销单。选它因为:贴合差旅/报销领域(有真实样例和验收标准)、不简单(抽取+四层门禁+防编造+分类+重试降级)、不复杂(输入输出结构化、验收可判)。

## 输入 → 输出

**输入**(贴入文字):
```
上海某餐饮 2026年8月12日 电子发票 号码 24317000000123456789
金额 428.00 元 税率 6% 税额 24.23 餐饮服务
```

**输出**(固定模板报销单):项目 / 金额(含税) / 税额 / 开票日期 / 发票号 / 类别 / 备注。

## 门禁四层（这个场景）

- **①结构**:金额/税额是数字>0;日期合法;发票号非空;类别∈{餐饮,交通,住宿,办公,其他}。
- **②规则**:税额≤金额;日期不晚于今天;税额与金额、税率对得上。
- **③对照(最值钱)**:金额/税额/发票号/日期必须能在输入原文找到依据——防编造、防改数。
- **④AI 评审(独立 agent)**:类别、备注等软判断兜底。

## 失败降级清单

待补交付 / 补一句再试 / 转人工 / 放弃。

## MVP 范围

- **做**:单段文字→单张报销单;四层门禁+重试+降级;清单勾选定合格标准。
- **不做**:拍照/OCR、多张批量、审批流对接、写入财务系统。

## 验收标准

- 真实发票文字样例 + 故意注入"改金额/编发票号"的坏样例 → 门禁挡坏放好。
- 出诚实的稳定性报告(通过率 + 翻车 case)。
- 一个非本人的纯新手能用清单勾选把这个 agent 配出来并用。

## 需要的插件(顺带摸底生态)

文本字段抽取(可能 LLM+schema 即可)、金额/日期规范化(可能自写)、独立评审 agent(自建)。摸底:生态里有没有现成的发票抽取/规范化插件——决定后续是"自由组合"还是"自建优先"。
